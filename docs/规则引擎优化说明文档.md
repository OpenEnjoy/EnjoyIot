## 1. 规则引擎优化

本次更新对规则引擎进行了全面优化，新增了**触发频率控制**、**延时触发**、**告警触发**和**告警解除**四大核心功能，使规则引擎更加灵活和智能。

### 1.1 触发频率控制

#### 功能描述
触发频率控制用于限制规则在指定时间间隔内只能触发一次，避免因设备频繁上报数据导致的告警风暴或重复执行问题。

#### 配置参数
| 参数名 | 类型 | 说明 |
|--------|------|------|
| `minIntervalSec` | Integer | 触发最小间隔（秒），为空或 ≤0 则不限制 |

#### 实现原理
- 基于 **Redisson RRateLimiter** 实现分布式限流
- 每个规则独立维护一个限流器，Key 格式：`rule:trigger:limit:{ruleId}`
- 采用滑动窗口算法，确保在指定时间窗口内只允许一次触发

#### 代码示例
```java
public boolean passRateLimit(Long ruleId, TriggerOptions options) {
    Integer minIntervalSec = options == null ? null : options.getMinIntervalSec();
    if (minIntervalSec == null || minIntervalSec <= 0) {
        return true;
    }
    RRateLimiter limiter = redissonClient.getRateLimiter(RATE_LIMITER_KEY_PREFIX + ruleId);
    limiter.trySetRate(RateType.OVERALL, 1, minIntervalSec, RateIntervalUnit.SECONDS);
    return limiter.tryAcquire();
}
```

#### 使用场景
- 温度传感器每秒上报数据，但告警只需每5分钟触发一次
- 防止网络抖动导致的重复告警

### 1.2 延时触发

#### 功能描述
延时触发允许规则在条件匹配后，延迟指定时间再执行动作。这对于需要确认状态持续性的场景非常有用。

#### 配置参数
| 参数名 | 类型 | 说明 |
|--------|------|------|
| `delaySec` | Integer | 延时触发时间（秒），为空或 ≤0 则即时触发 |

#### 实现原理
- 基于 **Redisson RDelayedQueue** 实现分布式延时队列
- 匹配成功后，将任务封装为 `TriggerJob` 投递到延时队列
- 后台消费线程在延时到期后执行实际动作

#### 核心数据结构
```java
@Data
public class TriggerJob implements Serializable {
    private Long ruleId;           // 规则ID
    private String messageJson;    // 设备消息JSON
    private boolean recovery;      // 是否为恢复任务
    private String recoverToken;   // 恢复任务令牌
    private Long tenantId;         // 租户ID
}
```

#### 执行流程
```
设备上报 → 监听器匹配 → 过滤器匹配 → 限频检查 → 延时队列 → 延时到期 → 执行动作
```

#### 使用场景
- 设备离线超过30秒才触发告警（避免网络瞬断误报）
- 温度超标持续1分钟才发送通知

### 1.3 告警触发

#### 功能描述
告警触发是规则引擎的核心功能，当设备数据满足预设条件时，自动执行告警动作（如发送短信、邮件、语音通知等）。

#### 实现优化
本次更新对告警触发进行了以下优化：

1. **租户上下文传递**：告警消息携带 `tenantId`，确保多租户环境下正确处理
2. **状态标记**：触发后自动标记为"告警中"状态，为告警解除提供依据
3. **日志记录**：完整记录触发过程，状态包括：
   - `matched_listener` - 监听器匹配
   - `matched_filter` - 过滤器匹配
   - `executed_action` - 动作执行完成

#### 告警消息结构
```java
@Data
public class Message {
    private String channelConfig;    // 通道配置
    private Long alertConfigId;      // 告警配置ID
    private String templateCode;     // 模板编码
    private Long tenantId;           // 租户ID（新增）
    // ...
}
```

### 1.4 告警解除

#### 功能描述
告警解除功能实现了告警的自动恢复机制。当设备数据恢复正常（不再满足告警条件）并持续一段时间后，系统自动发送告警解除通知。

#### 配置参数
| 参数名 | 类型 | 说明 |
|--------|------|------|
| `enableAlertRecover` | Boolean | 是否开启告警解除 |
| `recoverQuietSec` | Integer | 静默时间（秒），从最后一次匹配失败开始计算 |

#### 实现原理

1. **状态管理**：使用 Redis 存储规则的触发状态
```java
@Data
public class TriggerState implements Serializable {
    private boolean alerting;       // 是否处于告警中
    private String recoverToken;    // 恢复任务令牌（防止旧任务误恢复）
}
```

2. **恢复调度**：当数据不再匹配条件时，调度恢复任务
3. **令牌校验**：通过 `recoverToken` 机制防止旧的恢复任务误执行
4. **恢复脚本**：支持独立的恢复脚本，未配置则复用触发脚本

#### 执行流程
```
数据不匹配 → 检查是否告警中 → 生成恢复令牌 → 投递恢复队列 → 静默期到达 → 校验令牌 → 执行恢复动作
```

#### 取消恢复机制
如果在静默期内数据再次匹配告警条件，系统会：
1. 取消待执行的恢复任务（通过重置 token 实现）
2. 重新标记为告警状态

#### 代码示例
```java
public void scheduleRecoverIfNeeded(Rule rule, ThingModelMessage msg, TriggerOptions options) {
    if (options == null || !Boolean.TRUE.equals(options.getEnableAlertRecover())) {
        return;
    }
    TriggerState state = getState(rule.getId());
    if (state == null || !state.isAlerting()) {
        return;
    }
    // 生成新的恢复令牌
    String token = UUID.randomUUID().toString();
    state.setRecoverToken(token);
    saveState(rule.getId(), state);
    // 投递恢复任务
    TriggerJob job = new TriggerJob(rule.getId(), JsonUtils.toJsonString(msg), true, token, rule.getTenantId());
    recoverDelayedQueue.offer(job, options.getRecoverQuietSec() * 1000L, TimeUnit.MILLISECONDS);
}
```

## 2. 设备数据权限

### 功能描述
新增设备数据权限功能，实现基于部门的设备数据隔离。不同部门的用户只能查看和操作本部门及下级部门的设备数据。

### 实现方式

#### 1. 数据权限配置类
创建 `EiotDataPermissionConfiguration` 配置类，将设备表纳入数据权限管理：

```java
@Configuration(proxyBeanMethods = false)
public class EiotDataPermissionConfiguration {

    @Bean
    public DeptDataPermissionRuleCustomizer iotDeptDataPermissionRuleCustomizer() {
        return rule -> {
            // 设备表启用部门数据权限
            rule.addDeptColumn(EiotDeviceInfoDO.class);
        };
    }
}
```

#### 2. 设备创建时自动关联部门
在创建设备时，如果未显式指定部门，则自动使用当前登录用户的部门：

```java
@Override
public Long createDeviceInfo(EiotDeviceInfoSaveReqVO createReqVO) {
    // 若未显式传递机构，则默认使用当前登录用户机构，确保数据权限生效
    if (createReqVO.getDeptId() == null) {
        createReqVO.setDeptId(SecurityFrameworkUtils.getLoginUserDeptId());
    }
    // ... 后续创建逻辑
}
```

### 权限规则说明

| 数据权限类型 | 说明 |
|-------------|------|
| 全部数据 | 可查看所有设备 |
| 本部门数据 | 只能查看本部门的设备 |
| 本部门及下级 | 可查看本部门及所有下级部门的设备 |
| 仅本人数据 | 只能查看自己创建的设备 |
| 自定义 | 按配置的部门列表过滤 |

### 使用场景
- 集团公司下属多个分公司，各分公司只能管理自己的设备
- 项目组之间设备数据隔离
- 运维人员只能查看负责区域的设备

## 3. 设备详情页-设备配置

### 功能描述
新增设备配置功能，支持为每个设备存储和下发自定义配置。设备可以通过 MQTT 协议主动获取配置，实现远程配置管理。

### 核心功能

#### 1. 配置存储
- 支持 JSON 格式的配置内容
- 按设备维度存储，每个设备独立配置
- 支持配置的增删改查

#### 2. 配置下发
- 设备通过 MQTT 主题 `thing.config.get` 请求配置
- 服务端自动响应配置内容
- 支持网关子设备配置获取

#### 3. 配置缓存
- 使用 Redis 缓存配置数据
- 支持按设备ID和产品Key+DN两种方式缓存
- 配置更新时自动清除缓存

### 数据模型

#### 设备配置表 (eiot_device_config)
| 字段 | 类型 | 说明 |
|------|------|------|
| id | bigint | 主键 |
| config | text | 配置内容（JSON格式） |
| product_key | varchar | 产品Key |
| dn | varchar | 设备唯一编码 |
| tenant_id | bigint | 租户ID |
| create_time | datetime | 创建时间 |
| update_time | datetime | 更新时间 |

#### 配置DTO
```java
@Data
public class DeviceConfig {
    private Long id;
    private Long deviceId;
    private String deviceName;
    private String productKey;
    private String config;      // JSON格式配置内容
    private LocalDateTime createAt;
}
```

### MQTT 协议交互

#### 设备请求配置
**Topic**: `/{productKey}/{deviceName}/thing/config/get`

**Payload**:
```json
{
  "id": "123",
  "version": "1.0",
  "method": "thing.config.get"
}
```

#### 服务端响应
**Topic**: `/{productKey}/{deviceName}/thing/config/get_reply`

**Payload**:
```json
{
  "id": "123",
  "code": 0,
  "data": {
    "reportInterval": 60,
    "threshold": 100,
    "enableLog": true
  }
}
```

### 缓存策略

```java
// 按设备ID缓存
@Cacheable(cacheNames = "iot:deviceIdConfig", key = "#deviceId")
public DeviceConfig findByDeviceId(Long deviceId);

// 按产品Key+DN缓存
@Cacheable(cacheNames = "iot:deviceConfig", key = "#productKey+':'+#dn")
public DeviceConfig findByPkDn(String productKey, String dn);

// 保存时清除缓存
@Caching(evict = {
    @CacheEvict(cacheNames = "iot:deviceIdConfig", key = "#config.deviceId"),
    @CacheEvict(cacheNames = "iot:deviceConfig", key = "#config.productKey+':'+#config.deviceName")
})
public Boolean saveConfig(DeviceConfig config);
```

### API 接口

#### 获取设备配置
```
GET /eiot/device/config/{deviceId}
```

#### 保存设备配置
```
POST /eiot/device/config
Content-Type: application/json

{
  "deviceId": 123456,
  "config": "{\"reportInterval\":60,\"threshold\":100}"
}
```

### 使用场景
- 远程修改设备上报频率
- 下发设备工作参数（阈值、模式等）
- 设备固件升级配置
- 设备功能开关控制

## 总结

本次更新主要围绕以下三个方面进行了功能增强：

| 功能模块 | 核心价值 |
|---------|---------|
| 规则引擎优化 | 提供更精细的触发控制，支持限频、延时、自动恢复 |
| 设备数据权限 | 实现多租户/多部门的数据隔离，保障数据安全 |
| 设备配置管理 | 支持远程配置下发，提升设备管理灵活性 |

这些功能的实现充分利用了 Redis/Redisson 的分布式特性，确保在集群环境下的正确性和一致性。
